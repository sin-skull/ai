# データ設計（初期案）

保存先は IndexedDB。すべて端末内だけに置き、サーバーには送らない。スキーマの版は `settings.schemaVersion` で管理し、版が上がるときは移行処理を書く。

## ストア

| ストア | キー | 主な項目 |
| --- | --- | --- |
| terms（単語辞書） | 正規化した見出し語 | 定義、出典の一覧、作成日、更新日、使用回数、評価値 |
| passages（文章） | 自動採番のID | タイトル、出典URL、取得日、本文、関連する単語、使用回数、評価値、ピン留め |
| vectors（意味ベクトル） | passageId | ベクトル、使ったモデル名と版（モデルを変えたら作り直す） |
| ngram（転置インデックス） | n-gram文字列 | その文字列を含む passageId の一覧 |
| queue（未回答キュー） | 自動採番のID | 質問文、質問日、状態（未処理／調査済み／無視） |
| feedback（評価ログ） | 自動採番のID | 対象の種類とID、値（👍/👎）、日時、どの回答でか |
| settings（設定） | 設定名 | モード、モデルパック選択、中継のURL、schemaVersion |

## 整合性のルール

- passages の追加・削除は、ngram と vectors の更新を **同じトランザクション** で行う。
- passages を削除しても、terms は残す（残さない選択肢も用意する）。
- terms は同じ見出し語を2件持たない。重複したときは「上書き／追記／無視」を選ばせる。
- 外部から取得した文章には、必ず出典URL・取得日・ライセンス表記を持たせる。

## 評価軸（フェーズ6で使う）

評価（-1〜+1）、重要度（0〜1）、確信度（0〜1）、使用回数、最終使用日、取得日。詳細は [ROADMAP.md](ROADMAP.md) のフェーズ6を参照。

## 決定事項

- **schemaVersion**: IndexedDB の version と同じ整数（現在 1）。`settings.schemaVersion` にも保存する。上げるときは `js/db.js` の `migrations` に同じ番号の移行処理を足す。既存の番号の処理は書き換えない。
- **単語の正規化（terms のキー）**: NFKC（全角英数→半角、半角カナ→全角カナ、濁点の結合）→ カタカナをひらがなに → 英字は小文字 → 連続する空白を1つにして前後を除く。長音符「ー」は残す。漢字は変えない。
- **表示用の表記**: `term` に最初に保存した表記を残し、見かけた表記ゆれは `variants` に記録する。
- **定義が食い違ったとき**: `ask`（既定。書き込まず確認を返す）／`overwrite`／`append`／`ignore`。今の定義が空のときは衝突にせず補完する。
- **n-gram の長さ**: まず2-gram で始める。
