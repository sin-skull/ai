# 意味検索の評価

意味検索の設定（モデル・チャンクの大きさ・閾値など）を変えるたびに、同じ問題で数字を比べるための記録。

## 評価セット

- 文章 30件（`tests/eval/dataset.js`。自作）
- 質問 36件：言い換え 29件／言葉がそのまま入る 7件。それぞれ正解の文章が1つ決まっている
- 関係ない質問 6件：どの文章とも無関係。「関係ない」と捨てる閾値を決めるための確認用

## 実行のしかた

1. 公開URL（https）の `tests/eval.html` を開く（初回は約120MBのモデルを取得する）
2. 「実行」を押す。結果が画面に出る
3. 下の表に、日付・端末・設定と一緒に転記する

「疑似モデルで仕組みだけ確認」は、実モデルの代わりに文字2-gramのハッシュを使う。順位の数字は参考にならず、評価の仕組みが動くことの確認用。

## 見る数字

| 指標 | 意味 |
|---|---|
| 1位 | 正解の文章が1位に出た割合 |
| 3位以内／5位以内 | 上位に入った割合 |
| MRR | 正解の順位の逆数の平均（1.0が最高。出なければ0） |
| 近さの分布 | 正解が1位のときの意味検索の近さと、関係ない質問の最高の近さ。閾値はこの間に置く |

## 結果

| 日付 | 端末・ブラウザ | 設定 | 方式 | 1位 | 3位以内 | MRR | 備考 |
|---|---|---|---|---|---|---|---|
| 2026-10-12 | 利用者の端末（機種は未記入） | e5-small q8、チャンク300字、wasm | キーワード（ゆるい検索つき） | 50% | 50% | 0.500 | 言い換え 41%、言葉がそのまま入る 86% |
| 同上 | 同上 | 同上 | 意味のみ | 97% | 100% | 0.986 | 言い換え 97%、言葉がそのまま入る 100% |
| 同上 | 同上 | 同上 | ハイブリッド | 97% | 100% | 0.986 | 同上 |

速さ（同じ測定）：モデルの準備 27.9秒（初回・ダウンロード込み）／文章30件のベクトル作成 1.3秒（1件 44ms）／1回の検索 約22ms。

### 意味検索の近さ（閾値の根拠）

| | 最小 | 下位10% | 平均 | 最大 |
|---|---|---|---|---|
| 正解が1位のとき | 0.843 | 0.854 | 0.881 | |
| 関係ない質問（6件） | | | 0.804 | 0.831 |

- e5 の近さは 0.8〜0.9 に集まる（何にでも高めに出る）ので、近さの絶対値だけで「関係ある」とは言えない。
- 2つの分布は重ならなかったが、差は 0.012 しかない。**閾値は 0.84** に置いた（`js/app.js` の `SEMANTIC_MIN`）。
- 関係ない質問は6件しかない。文章が増える、質問の種類が増えると線は動くので、測り直す。

### 読み取れること

- 言い換えの質問は、キーワードだけだと 41% しか1位に出ないが、意味検索を入れると 97%。意味検索の価値ははっきり出ている。
- この評価セットでは、ハイブリッドは意味のみと同じ（言葉がそのまま入る質問も意味検索が100%で取れた）。ハイブリッドの利点（固有名詞・型番・数字）が出る質問が、まだ評価セットに足りない。次に足す。
- 実モデルは、機内モード相当（オフライン）での動作が未測定。

### 参考：疑似モデルでの仕組み確認（実モデルの精度ではない）

キーワード検索にゆるい検索を足したことで、キーワードのみの1位は 6% → 50% になった（同じ評価セット）。
